# Simulation of information system states for reliability assessment

Code, input data, and results for the article _Simulation of information system
states for reliability assessment in the context of business digital
transformation_.

## Overview

The information system is represented by a discrete-time multi-state model
with five mutually exclusive states: the normal operating state $S_1$, degraded
operating state $S_2$, partial failure state $S_3$, critical failure state $S_4$
and recovery state $S_5$. The admissible transition matrix $A$ defines which
state transitions are possible, and a transition probability matrix $P$ per
architecture defines their probabilities. Each Monte Carlo simulation run
generates one system state trajectory $s(t)$ with an hourly simulation time
step over one year ($H = 8760$) and accumulates the total economic loss (Eq. 10
of the article)

```math
L = \sum_{t=1}^{H} C_{s(t)} \, q(t),
```

where $C_i$ is the state-specific cost rate of $S_i$ and $q(t)$ the
time-dependent business criticality coefficient. Repeated runs give the
estimated expected economic loss $\hat{E}(L)$, the loss quantiles $L_{95}$ and
$L_{99}$, generalized multi-state availability $K_{av}^{(n)}$, the empirical
exceedance frequency of the acceptable loss threshold $L_{allow}$, and the net
economic benefit $NEB$ of two reliability improvement measures relative to the
baseline architecture:

- A0 - baseline architecture,
- A1 - hot-standby architecture,
- A2 - fault-tolerant architecture with automatic failover.

All parameters are synthetic (expert-specified, illustrative), and all monetary
values are in illustrative monetary units (MU).

## Requirements

Python 3.13 (results were produced with CPython 3.13.9 on macOS, arm64). The
direct dependencies are NumPy, pandas, and Matplotlib; `requirements.txt` pins
the exact versions used, including Matplotlib's own dependencies.

## Installation

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -e . --no-deps
```

## Reproducing the experiments

Run from the repository root, in this order:

```bash
python scripts/run_simulation.py            # Table 4, Fig. 4 data   (~3.5 min)
python scripts/run_stability_analysis.py    # pilot runs, choice of R (~40 s)
python scripts/generate_figures.py          # Figs. 2-4               (~10 s)
python scripts/run_sensitivity_analysis.py  # Table 5                 (~12 min)
python scripts/check_article_values.py      # compare with the article
```

`run_stability_analysis.py` and `generate_figures.py` read the samples written
by `run_simulation.py`. `run_sensitivity_analysis.py` is independent.

`check_article_values.py` compares every number reported in the article
(Tables 4 and 5, the pilot and stabilization results, and the values quoted in
the text) with the regenerated outputs at the precision printed in the article,
and compares Figs. 2-4 byte for byte with the images in the manuscript. It exits
with a non-zero status on any mismatch. Because `outputs/` is under version
control, `git status outputs/` after a rerun also shows whether any output file
changed.

```bash
pytest                                      # unit tests (~6 s) and the article check
```

## Data

All input files in `data/input/` are synthetic. They were specified by the
authors for the illustrative experiment, and are not derived from any real
information system or organization; no personal data is included.

| File                                                         | Contents                                                                                              |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `states.csv`                                                 | five states, functional-availability flags ($W = \lbrace S_1, S_2 \rbrace$), cost rates $C_i$ in MU/h |
| `admissible_transitions.csv`                                 | admissible transition matrix $A$ (Table 2)                                                            |
| `transition_probability_matrix_a0.csv`, `_a1.csv`, `_a2.csv` | transition probability matrix $P$ per architecture                                                    |
| `architectures.csv`                                          | architectures and annualized costs $I$ in MU/year                                                     |
| `business_criticality_profile.csv`                           | weekly hourly profile of $q(t)$, 168 values, repeated over the horizon                                |

`config/parameters.json` holds the experiment settings: horizon, adopted and
checked run counts, seeds, initial state, confidence level, target relative
margin of error (5 %), stabilization threshold (1 %), and the acceptable annual
loss threshold $L_{allow} = 110\,000$ MU/year
(`acceptable_annual_loss_threshold_mu`).

## Reproducibility

- Randomness comes only from `numpy.random.default_rng` (PCG64). The main
  experiment and the sensitivity analysis use seed 42, the pilot simulation seed
  2025 (`config/parameters.json`).
- Each run draws exactly $H$ uniform random numbers, and every architecture is simulated from
  the same seed, so all architectures and all sensitivity scenarios share the
  same random-number stream (common random numbers).
- The main experiment simulates 5 000 runs per architecture. The tables at
  $R = 3000$ and the stabilization check at
  $R \in \lbrace 500, 1000, 2000, 3000, 5000 \rbrace$ use the first $R$ runs of
  that sample. The pilot uses a separate series of
  1 000 runs.
- With the pinned environment, reruns are bit-for-bit identical, including the
  PNG files. Other NumPy or pandas versions are expected to give the same
  numbers, and other Matplotlib or FreeType versions may change figure bytes but
  not the plotted data. `REPRODUCIBILITY.md` gives the validation record.

## Limitations

The results illustrate the method and are not forecasts for a real information
system.

- All inputs are synthetic: $P$, $C_i$, $q(t)$, $I$ and $L_{allow}$.
- Transition probabilities are time-invariant. The system is represented by a
  single aggregated state, without subsystem dependencies or common-cause
  failures.
- $q(t)$ scales the entire state-specific cost rate, although some recovery
  costs and penalties may not vary with business activity.
- Loss quantiles and exceedance frequencies are empirical estimates. Observing
  no exceedance in 3 000 runs (0/3 000) does not imply a zero theoretical
  exceedance probability.
- The sensitivity analysis varies parameter groups one at a time over assumed
  ranges; these ranges are not confidence intervals.
- The annual comparison does not include discounting or life-cycle costs.

The ranking of A2 first by $NEB$ in the baseline configuration and all 13
parameter-variation scenarios are conditional on these inputs.

## Using empirical data

To apply the model to another system, replace the files in `data/input/` and
the criteria in `config/parameters.json`. From incident logs or monitoring
data, $p_{ij} = N_{ij} / \sum_j N_{ij}$, where $N_{ij}$ is the observed number
of transitions from $S_i$ to $S_j$. Every row of $P$ must sum to one and keep
the structural zeros of $A$; matrices that violate either condition are
rejected when loaded. `scripts/check_article_values.py` applies only to the
published inputs.
